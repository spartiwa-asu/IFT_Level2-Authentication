Test the API end to end with Postman

    Test the Level 2 API with Postman

    You will sign up, log in, copy your token, authorize your requests with it, and then create, read, update and delete games and scores. At the end you will run the whole thing in one click.

    Responses marked real response were recorded from this project's API. Pictures of Postman's window are marked illustration: they show which box to use, not a screenshot. Postman's layout changes between versions, so look for the same labels.

    STEP 1 Before you start

    1. Start the API in the project folder and wait for DB connection successful:
      npm start
    2. Install the Postman desktop app from postman.com/downloads and sign in, or use it without an account if it offers that.
    3. Using Postman in a web browser instead? It cannot reach localhost on its own. Install the Postman Desktop Agent when it asks, and choose it in the agent selector at the bottom right. The desktop app needs no agent.

    Why Postman never shows a CORS error: CORS is enforced by web browsers. Postman is not a browser page, so it ignores CORS_ORIGINS. If a request works in Postman but not in the browser client, the difference is CORS.

    1. Set the method to POST and paste the URL.

    STEP 5 Authorize the request with your token

    The API expects this exact header: Authorization: Bearer <token>, which is the word Bearer, one space, then the token. Postman gives you two ways to send it. Whether you type the word "Bearer" depends on which way you use.

    Way 1 · Authorization tab (recommended)

    Paste ONLY the token. Do NOT type "Bearer".
    1. Open the Authorization tab (called Auth in some versions).
    2. Set Auth Type to Bearer Token.
    3. Paste the 64-character token into the Token box.
    4. Click Send.

    Postman adds the word Bearer and the space for you. To check, open Headers and show the hidden headers: you will see Authorization: Bearer c716ab….

    Authorization tabillustration
    GEThttp://localhost:4001/api/v1/gamesSend
    ParamsAuthorizationHeadersBody
    Bearer Token ▾
    c716aba0df1b410ab3c69901fa045192cdaa82709a29a3a4670d4e4fb76d3e79
    ↑ just the token. Postman sends "Bearer " + this.

    Way 2 · Headers tab (by hand)

    Type "Bearer", one space, then the token.
    1. In the Authorization tab, set Auth Type to No Auth, so Postman does not add a second header.
    2. Open Headers and add a row:
      Key Authorization
      Value Bearer c716ab…
    3. Click Send.

    Here nothing is added for you. The value must start with Bearer followed by exactly one space.

    STEP 6 Common "Bearer" mistakes

    Every row was sent to the real API. The last three all get the same 401: for safety, the server does not say which part was wrong.

    What you didHeader the server receivedResult
    Way 1, token only in the Bearer Token boxAuthorization: Bearer c716ab…200
    Way 2, typed Bearer c716ab… in HeadersAuthorization: Bearer c716ab…200
    Typed Bearer c716ab… in the Bearer Token boxAuthorization: Bearer Bearer c716ab…401
    Way 2 without the word: value c716ab…Authorization: c716ab…401
    Auth Type left on No Auth and no header(none)401
    Copied the quotes: "c716ab…"Authorization: Bearer "c716ab…"401
    Token from before the API's database was reseeded, or older than 24 hoursAuthorization: Bearer <old token>401

    Why so strict? middleware/authenticate.js accepts only Bearer, one space, and exactly 64 hex characters: /^Bearer ([a-f0-9]{64})$/i. Anything else is rejected before the database is even asked.

    STEP 8 Run everything in one click

    The file postman-guide/IFT458-Level2.postman_collection.json contains all 17 requests, with tests. Log in saves the token for you, so you never paste it.

    1. In Postman, click Import (or File → Import) and drop in IFT458-Level2.postman_collection.json.
    2. Open the collection and look at its Authorization tab: Auth Type Bearer Token, Token {{token}}. Every request set to Inherit auth from parent uses it.
    3. Open the Variables tab. baseUrl is http://localhost:4001/api/v1. Change it only if your API runs somewhere else.
    4. Click the collection's ⋯ menu → Run collection (the Collection Runner), keep the order, and click Run.

    How the token gets saved

    The Log in request has this script. It is in the Scripts → Post-response tab, called Tests in older Postman versions:

    // Saved WITHOUT the word Bearer: the collection's Bearer Token auth adds "Bearer " itself
const token = pm.response.json().token;
pm.collectionVariables.set("token", token);

    This is Way 1 again: the variable holds only the token, and the Bearer Token auth adds Bearer . Sign up makes a new email on every run, so you can run the collection again without a 409.

    STEP 9 Troubleshooting

    401 "Authentication required" on games or scores
    1. Is Auth Type Bearer Token with only the token (Way 1), or a header Bearer <token> with Auth Type No Auth (Way 2)? Use the checker in Step 5.
    2. Did you copy the quotes, a space, or only part of the token?
    3. Is the token older than 24 hours, or from before npm run seed wiped the database? Log in again for a new one.
    4. The API terminal prints a checklist under every 401. Read it.
    401 "Incorrect email or password." on login

    The email or password is wrong. The message is the same for both, on purpose, so attackers cannot learn which emails exist. Seeded users use password12345.

    "Could not send request" / ECONNREFUSED

    The API is not running, or it is on a different port. Run npm start and check the Ready lines. In Postman on the web, select the Desktop Agent. The cloud agent cannot reach localhost.

    400 on signup or create

    Check the Body tab is raw → JSON, not Text, and that the field names match exactly: they are case sensitive. The response's message names the failing field.

    409 on signup

    That email is already registered. Use a new one, or log in with it instead.
